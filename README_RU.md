Порт **k5prog-win v0.1.26** (OneOfEleven) для macOS, с доработками.

Нативное приложение для macOS: резервное копирование, восстановление и прошивка радиостанций
**Quansheng UV-K5 / UV-K5(8) / UV-K6 / UV-5R Plus** (V1, DP32G030) и **UV-K5 V3 / UV-K1** (PY32F071)
через кабель программирования.

Поведение [k5prog-win](https://github.com/OneOfEleven/k5prog-win) сохранено один в один (те же
кнопки, тот же лог, те же байты в линии). Добавлено то, чего k5prog-win не умеет: загрузка прошивки
в новые UV-K5 V3 и UV-K1, редактор каналов, а также несколько исправлений для большей безопасности
(см. [Отличия от k5prog-win](#отличия-от-k5prog-win)).

## Возможности

- **Чтение / запись калибровки** (512 байт по адресу `0x1E00`). Сохраните заводскую калибровку
  радиостанции, прежде чем что-либо прошивать.
- **Чтение / запись конфигурации** (каналы и настройки, `0x0000–0x1CFF`).
- **Запись прошивки**: «сырой» `.bin` или фирменный `.packed.bin`. Тип радиостанции определяется по
  самому образу и сверяется с загрузчиком до того, как что-либо будет записано.
- **Memory Editor** (редактор каналов) для 200 каналов радиостанции: стоковая прошивка и Karina,
  UV-K5 V1 и UV-K1 / UV-K5 V3 (см. [Редактирование каналов](#редактирование-каналов)). Правка,
  копирование и перетаскивание каналов между двумя радиостанциями, импорт / экспорт CHIRP CSV и
  CHIRP `.img`, текст при включении на стоковой прошивке. Записываются только изменённые каналы,
  после создания резервной копии, а затем они считываются обратно для проверки. Настройки и
  калибровка никогда не затрагиваются.
- **Состояние радиостанции** в главном окне: какая радиостанция подключена к кабелю, в каком
  режиме и какая у неё строка прошивки. Проверка идёт в фоне каждые 2 секунды.
- **Настройки** (**K5K1 Prog → Settings…**): светлое / тёмное оформление, папка для резервных копий
  редактора.
- Универсальное приложение (Apple Silicon и Intel), macOS 12 или новее. Для кабелей на CH340 не
  нужны ни драйверы, ни дополнительные программы.
- Настройки (порт, скорость, уровень подробности лога, положение окна, оформление) хранятся так, как
  принято в macOS, в `~/Library/Preferences/io.github.eruban.k5k1prog.plist`. Рядом с приложением
  ничего не записывается.

## Поддерживаемые радиостанции

| Радиостанция | MCU | Загрузчик | Калибровка / конфигурация | Прошивка |
|---|---|---|---|---|
| UV-K5, UV-K5(8), UV-K6, UV-5R Plus ("V1") | DP32G030 | 2.x – 4.x | ✅ | ✅ (протокол k5prog-win) |
| UV-K5 V3, UV-K1 | PY32F071 | 7.xx (7.00.07 или новее) | ✅ | ✅ |
| UV-K5 V2, UV-K6 V2 | PY32F030 | 1.xx | ✅ | ❌ отклоняется |

Модель указана под аккумулятором (V2, V3), но надёжнее ориентироваться на версию загрузчика:
переведите радиостанцию в режим загрузчика и нажмите **Write Firmware**, в логе появится
`Bootloader version '…'`.
Радиостанции UV-5R Plus Type-C с загрузчиком 5.x используют зашифрованный протокол загрузчика и не
поддерживаются.

Проверено на реальном оборудовании: UV-K5 V1 (загрузчик 2.00.06) и UV-K1 (загрузчик 7.03.01). Обе
радиостанции прошиты с помощью K5K1 Prog, с обеих считаны калибровка и конфигурация, а в UV-K1
калибровка была записана и проверена обратным чтением.

> [!WARNING]
> Прошивки для радиостанций V1, V2 и V3/K1 **не взаимозаменяемы**. K5K1 Prog проверяет это, прежде
> чем что-либо отправить: образ V1 для загрузчика 7.xx, образ V3/K1 для любого другого загрузчика и
> любой образ для загрузчика V2 (1.xx) отклоняются.
>
> Программа **не может отличить образ UV-K1 от образа UV-K5 V3** (тот же чип, тот же загрузчик, и
> загрузчик не сообщает модель). Выбирайте файл для своей модели. Если прошить не тот файл,
> радиостанция может работать неправильно или не запуститься, но загрузчик при этом не
> перезаписывается: включите радиостанцию с зажатой кнопкой **PTT** и прошейте правильный файл.
>
> Прошивка выполняется на ваш собственный риск.

## Установка

Через [Homebrew](https://brew.sh):

```sh
brew install --cask eruban/tap/k5k1-prog
```

`brew upgrade` устанавливает новые версии (cask в [ERuban/homebrew-tap](https://github.com/ERuban/homebrew-tap)
сам обновляется с каждым релизом).

Или скачайте `K5K1-Prog-<version>.dmg` со страницы [Releases](../../releases), откройте его и
перетащите **K5K1 Prog** в **Applications**. Приложение подписано сертификатом Developer ID и
нотаризовано Apple, поэтому открывается без предупреждений. К релизу также приложен `.zip` с тем же
приложением.

Начиная с версии 1.1.0 приложение обновляется само: раз в день (а также по команде
**K5K1 Prog → Check for Updates…**) оно проверяет, нет ли на GitHub нового релиза, показывает, что
изменилось, и устанавливает обновление в один клик ([Sparkle](https://sparkle-project.org),
обновления подписаны EdDSA). В версии 1.0.0 механизма обновления нет, поэтому 1.1.0 нужно один раз
установить вручную.

Или соберите из исходников (нужны Xcode Command Line Tools и Swift 5.9 или новее):

```sh
git clone <this repository> k5k1prog-mac && cd k5k1prog-mac
./scripts/build_app.sh        # -> "K5K1 Prog.app" in the repository root (ad-hoc signed)
open "K5K1 Prog.app"
```

## Использование

Подключите радиостанцию кабелем программирования (двухконтактный разъём Kenwood). Кабель появляется
как `/dev/cu.usbserial-…` (или `/dev/cu.wchusbserial…`, если установлен драйвер WCH). Выберите его в
поле **Serial port** и оставьте скорость **38400 - k5/k6**.

### Сначала резервная копия

1. Включите радиостанцию обычным образом.
2. Нажмите **Read Calibration** и сохраните файл в надёжном месте. В нём калибровка мощности
   передатчика и аккумулятора именно вашей радиостанции, и взять её больше негде.
3. Нажмите **Read Configuration** и сохраните файл.

Калибровка и конфигурация записываются обратно так же (**Write Calibration**,
**Write Configuration**), радиостанция при этом включена обычным образом.

### Запись прошивки

1. Выключите радиостанцию, зажмите **PTT** и включите её. Экран останется пустым: радиостанция
   в режиме загрузчика.
2. Нажмите **Write Firmware** и выберите `.bin` (или `.packed.bin`) для своей модели.
3. Проверьте лог: `Bootloader version '…'` начинается с `2`–`4` у радиостанций V1 и с `7` у V3/K1.
4. Дождитесь `write FLASH complete`. Радиостанция перезапустится с новой прошивкой.

Дальше следуйте инструкциям к своей прошивке (сброс памяти, какие файлы калибровки загружать и так
далее). Некоторые пакеты прошивок содержат полный файл калибровки, который заменяет заводские
значения мощности передатчика и аккумулятора. После прошивки сделайте **Read Calibration** и
сравните результат со своей резервной копией.

### Редактирование каналов

1. Включите радиостанцию обычным образом, выберите её порт и нажмите **Memory Editor…** (⌘E). Каналы
   считываются из радиостанции; окно всегда показывает то, что записано в радиостанции сейчас.
2. **Firmware** и **Radio** определяются по строке прошивки радиостанции: стоковая прошивка — по
   номеру версии, Karina — по её кодовому имени. У Karina эта строка одинакова на UV-K5 V1 и UV-K1,
   поэтому редактор один раз спрашивает, какая это радиостанция. Незнакомая прошивка открывается
   только для чтения, пока вы не сделаете выбор. Если выбрать то, что противоречит строке прошивки,
   редактор предупредит об этом красным: значения каналов (режим, шаг, скремблер) будут прочитаны и
   записаны неправильно.
3. Чтобы изменить ячейку, дважды щёлкните по ней. Выделите несколько каналов, чтобы изменить их
   вместе: **Set Power**, **Delete**, ⌘Z — отмена.
4. **Write to Radio…** показывает список изменений, сохраняет резервную копию конфигурации
   радиостанции (`~/Documents/K5K1 Prog Backups/`, см. настройки), проверяет, что радиостанция не
   изменилась с момента чтения, записывает только изменённые блоки, считывает их обратно и
   сравнивает. Резервная копия восстанавливается через **Write Configuration**.

Чтобы скопировать каналы в другую радиостанцию, откройте редактор для каждой из них (по одному на
порт) и перетащите каналы из одного окна в другое или воспользуйтесь Copy / Paste. Другой вариант —
**Export Channels…** в одном редакторе и **Import Channels…** в другом. Значения, которых нет в
другой прошивке (USB на стоковой прошивке, список скремблеров Karina, мелкие шаги), преобразуются,
и программа выводит их список. При импорте номера каналов сохраняются, настройки из файла
игнорируются. Форматы: CHIRP CSV, CHIRP `.img` (стоковая прошивка или Karina, UV-K5 / UV-K1) и
`.bin` конфигурации, полученный через Read Configuration (по `.bin` нельзя понять, с какой он
радиостанции: выберите её в диалоге импорта).

Пока окно редактора активно, он проверяет радиостанцию каждые 2 секунды. Если подключена другая
радиостанция, редактор считывает её (а если есть незаписанные правки, сообщает об этом и не пишет в
неё).

Редактируется только память каналов (200 каналов в стоковой раскладке, общей для стоковой прошивки,
Karina и F4HWN). Другие прошивки, больше 200 каналов (F4HWN на UV-K1) и настройки радиостанции не
поддерживаются.

## Отличия от k5prog-win

Все отличия — в сторону безопасности:

1. **Загрузка прошивки в UV-K5 V3 / UV-K1** (PY32F071, загрузчик 7.xx), см. ниже.
2. Файл прошивки для V1 (DP32G030) никогда не отправляется на загрузчик 7.xx, а загрузка прошивки в
   UV-K5 V2 / K6 V2 (загрузчик 1.xx, PY32F030) отклоняется: после прошивки для V1 у такой
   радиостанции остаётся пустой экран.
3. **Файл конфигурации, размер которого не кратен 128 байтам.** k5prog-win читает за концом своего
   буфера и записывает в радиостанцию случайное содержимое памяти. Здесь в остатке последнего блока
   сохраняются собственные байты радиостанции (сначала они считываются). Обычных файлов
   (7424 / 8192 / 512 байт) это не касается.
4. В списке портов показываются `/dev/cu.*` (аналог списка COM-портов в macOS). В строке состояния
   нет индикатора "RX BREAK".
5. Главное окно не опрашивает радиостанцию с выводом в лог при запуске и при смене порта ("Fetching
   radio details .. radio not detected"). Вместо этого состояние радиостанции показывается в строке
   состояния, и от него зависят кнопки: для конфигурации, калибровки и редактора радиостанция должна
   быть в обычном режиме, для Write Firmware — в режиме обновления прошивки, а без радиостанции
   ничего не активно. Длинные строки лога переносятся.
6. **Настройки** хранятся в настройках macOS (`io.github.eruban.k5k1prog`), а не в ini-файле рядом с
   приложением: на Mac эта папка — `/Applications`. Ключи те же, что в `k5prog_win.ini`
   (`MainForm.Top`, `GUI.Verbose`, `SerialPort.Name`, …). Версии 1.0 / 1.1 использовали
   `K5K1Prog.ini`; он один раз импортируется и удаляется. Диалоги выбора файлов открываются в
   `~/Documents`.

Всё остальное совпадает с оригиналом: кнопки, порядок операций, тайм-ауты (hello 2×1 с, чтение 3 с,
запись 2 с, прошивка 3 с), повторы, проверки, все строки лога и тексты окон сообщений, протокол
(кадры, таблицы XOR, CRC, идентификатор сеанса `6A 39 57 64`, блоки конфигурации по 128 байт, блоки
прошивки по 256 байт, исправление версии загрузчика `4.00.07` → `*.00.07`), ключи настроек и Esc
для прерывания передачи.

## Загрузка прошивки в UV-K5 V3 / UV-K1

**Write Firmware** определяет тип файла по таблице векторов: у образа PY32F071 вектор сброса указывает
на `0x080xxxxx`, у образа DP32G030 — на `0x0000xxxx`. Для обоих типов принимаются «сырые» `.bin` и
фирменные `.packed.bin`. Файлы для V1 идут по прежнему пути k5prog-win, без изменений.

Протокол PY32 (как в serialtool от muzkr):

- версия загрузчика должна начинаться с `7` и быть `7.00.07` или новее, иначе ничего не отправляется;
- 5 корректных интервалов маяка `0x0518` (5–1000 мс) подряд, затем `0x0530` с первыми 4 символами
  версии загрузчика, по одному на каждый маяк, 3 раза;
- страницы `0x0519`: метка времени LE32, номер страницы LE16, число страниц LE16, 4 × `00`, 256 байт
  данных (последняя страница дополняется `00`); ответ `0x051A`: метка времени / страница / ошибка;
  3 с на страницу, до 3 повторных отправок страницы после ошибки или при отсутствии ответа;
- максимальный размер образа `0x1D800` (область приложения начинается с `0x08002800`, 118 КБ);
- команды перезагрузки в конце нет, загрузчик сам запускает новую прошивку.

Неверные комбинации отклоняются до того, как что-либо будет записано: файл для V1 на загрузчике
7.xx, файл для V3/K1 на любом другом загрузчике, любой файл на загрузчике V2 (1.xx), загрузчик
версии ниже 7.00.07, слишком большой образ, радиостанция не в режиме загрузчика.

## Разработка

Вклад в проект приветствуется: см. [CONTRIBUTING.md](CONTRIBUTING.md) (а для ИИ-агентов, которые
пишут код, — [AGENTS.md](AGENTS.md); оба файла на английском).

```sh
swift test                    # 76 tests: simulator, protocol, reference comparisons, channels
swift run k5emu --mode boot --bl-version 7.03.01 --link /tmp/k5com   # simulated K1 bootloader
```

- `Sources/K5Core`: протокол, работа с файлами прошивки, логика k5prog-win; `Channels.swift` и
  `ChannelTransfer.swift` — для Memory Editor (раскладка каналов, профили, CSV / `.img`).
- `Sources/K5K1Prog`: приложение на AppKit.
- `docs/`: сайт (GitHub Pages, пять языков), его генерирует `scripts/build_site.py`; тексты правьте
  в этом скрипте и затем запускайте его.
- `scripts/chirp-golden/golden.py`: строит эталоны для тестов каналов с помощью настоящих драйверов
  CHIRP (синтетические образы, без персональных данных). Нужен только при изменении профилей.
- `Sources/K5Sim`, `Sources/k5emu`: симулятор UV-K5 на псевдотерминале. Обычный режим, загрузчик V1
  и `--bl-version 7.xx.xx` для загрузчика PY32. Имитация сбоев (отклонённые или потерянные страницы)
  настраивается в `RadioSim.Options`.
- Тестам не нужны файлы прошивок: при загрузке прошивки (V1 и PY32, «сырой» и `.packed`)
  используются синтетические образы с корректной таблицей векторов.
- GitHub Actions (`.github/workflows/tests.yml`) собирает проект, запускает тесты и собирает бандл
  приложения при каждом push и pull request.

Релиз: увеличьте `K5.version` в `Sources/K5Core/Constants.swift`, напишите
`release-notes/<version>.md`, затем запустите `./scripts/release.sh`. Скрипт запускает тесты,
собирает универсальное приложение, подписывает его и встроенный фреймворк Sparkle сертификатом
"Developer ID Application" (hardened runtime), нотаризует приложение и `.dmg` и прикрепляет к ним
тикет нотаризации (staple), подписывает `.zip` обновления ключом Sparkle EdDSA и формирует `dist/`
(`.dmg`, `.zip`, `appcast.xml`, `SHA256SUMS.txt`, `RELEASE_NOTES.md`). Приложите все эти файлы к
релизу на GitHub: установленные копии читают `releases/latest/download/appcast.xml`. Разовая
настройка (профиль notarytool, ключ Sparkle в `Resources/SparklePublicKey.txt`) описана в заголовке
скрипта. Сам скрипт ничего не публикует.

Тестовые хуки (для обычной работы не нужны):

- `K5PROG_EXTRA_PORTS=/tmp/k5com` добавляет пути устройств в список портов (для `k5emu --link /tmp/k5com`).
- `K5PROG_UITEST=readcalib,writecalib,quit` вместе с `K5PROG_UITEST_OPEN/SAVE/MEMO` управляет
  настоящим приложением без диалогов (а также `editor`, `editor-import`, `editor-write`,
  `editor-export`, `snap` с `K5PROG_UITEST_SNAP=<dir>` для снимков окон, `wait`; полный список — в
  [AGENTS.md](AGENTS.md), на английском).
- `K5PROG_BACKUP_DIR=<dir>` задаёт папку для резервных копий Memory Editor.
- `K5PROG_CHANNEL_DUMPS=<dir>` сравнивает декодирование каналов из ваших собственных дампов с
  результатом CHIRP (`<name>.<profile>.bin` + вывод `golden.py --decode` в виде `.json`).
- `K5PROG_SETTINGS_SUITE=<name>` хранит настройки отладочного / тестового запуска отдельно от
  настоящих (и пропускает импорт старого `K5K1Prog.ini`).
- `K5PROG_SPARKLE_FEED=<url>` направляет механизм обновления на другой appcast (локальные тесты
  обновлений, `open --env K5PROG_SPARKLE_FEED=… "K5K1 Prog.app"`).
